# 需求描述（Me2AI）

> 只写“需求事实”，不要写实现方案。

## 1) 项目概述
- 项目目标：在现有 spec 模式下，补齐 Me2AI 与 AI2AI 的本轮需求，使系统可根据给定公众号链接与用户思考，生成一篇新的公众号文章并保存到对应草稿箱。
- 面向用户：需要进行公众号内容再创作的内容运营者。
- 核心价值：把“输入链接 + 输入想法”转成“可直接进入草稿箱的新稿件”。

## 2) 核心玩法 / 功能
- 功能列表（按优先级）：
  1. 输入一个公众号文章链接。
  2. 输入用户自己的想法与思考。
  3. 生成新的公众号文章内容。
  4. 将生成结果写入对应公众号草稿箱。
- 用户主流程（步骤）：
  1. 提供公众号链接。
  2. 提供想法与思考。
  3. 触发生成。
  4. 在对应草稿箱看到新生成稿件。

## 3) 边界与非目标（非常重要）
- 本阶段明确不做：
  - 不新增与“链接+思考→生成并入草稿箱”无关的功能。
  - 不扩展多平台分发、自动发布、数据分析等能力。
- 不允许 AI 自己加的内容：
  - 不得自行补充未被明确要求的业务流程或产品能力。

## 4) 验收口径（必须可验证）
- 通过标准：
  - 给定一个有效公众号链接与用户思考后，系统能够产出新文章并成功进入对应草稿箱。
- 必须提供的证据（命令/截图/日志/链接）：
  - AI2AI 中记录本次迭代的验证命令与验证结果摘要。

## 5) 迭代划分（可选，但强烈推荐）
- 迭代 1：完成需求在 Me2AI 与 AI2AI 的对齐与固化。
- 迭代 2：在代码层实现“链接+思考→新稿→草稿箱”。
